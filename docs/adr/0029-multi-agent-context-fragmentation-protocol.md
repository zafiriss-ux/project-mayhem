# ADR-0029 — Multi-Agent Context Fragmentation Protocol

**Date:** 2026-03-06
**Status:** Accepted
**Deciders:** Architect
**Source:** Architect Observations V6 — Risk #5 (Multi-Agent Fragmentation) + Risk #1 (Agent Context Drift) + Risk #11 (Agent Black Box Implementation)
**Phase:** 7.8 Hardening
**Supplements:** ADR-0025 (Agent Context Continuity Protocol)

---

## Context

TITAN OS is developed and maintained using a **multi-agent stack**:

| Role | Tool | Responsibility |
|---|---|---|
| Advisor | ChatGPT | High-level strategy, brainstorming |
| Advisor | Gemini | Second-opinion technical review |
| Advisor | Claude Chat | Architecture discussions |
| Engineer | Codex (AGENTS.md) | Automated implementation tasks |
| Architect | Claude Code | ADRs, governance, code review |

### The Fragmentation Problem

ADR-0025 addresses *single-agent* context drift: one Claude Code session loses context
between sessions. This ADR addresses *multi-agent* fragmentation: **different AI tools
operating on the same codebase simultaneously, each with a different and potentially
contradictory understanding of the system's current state.**

Observed failure modes:

**FM-1 — Advisor/Implementer Divergence:**
An advisor (ChatGPT, Gemini) recommends a pattern based on general best practices.
The implementer (Codex, Claude Code) implements it without knowing it contradicts an
existing ADR. Example: an advisor recommends "add a retry decorator to all Garmin sync
calls"; the implementer adds it; this violates ADR-0020 (persistence failure policy)
which specifies *conservative degraded mode* rather than retries.

**FM-2 — Stale-ADR Advice:**
An advisor is given an outdated version of CLAUDE.md or no context at all. The advice
is based on Phase 5 architecture while the system is at Phase 7.8. The implementation
of the advice introduces regressions against Phase 7 decisions.

**FM-3 — Parallel Agent Conflict:**
Two agents (e.g., Codex running a task and Claude Code reviewing) operate on different
mental models of which debt items are open. One closes a debt item by fixing the symptom;
the other closes it by fixing the root cause. Both PRs are opened; one is merged; the
other introduces a regression when merged.

**FM-4 — Context-Free Advisory Approval:**
The architect approves an advisor's recommendation without checking it against the ADR
register. The implementation follows the recommendation faithfully — but it violates
an architectural invariant that neither the advisor nor the implementer knew about.

---

## Decision

**Introduce a Context Handoff Artifact that must be provided to any AI tool before it
can produce advice or implementation for this codebase. Advisors operate on the artifact,
not on a free-form description.**

### The Context Handoff Artifact

A machine-generated snapshot of the current codebase state, placed at:

```
docs/context-snapshot.md
```

**Generated by:**
```bash
python scripts/generate_context_snapshot.py
```

**Contents (auto-generated, do not edit manually):**

```markdown
# TITAN OS — Context Snapshot
Generated: {timestamp}

## System Version
v{version} — Phase {phase} — {status}

## Open Debt Items (Tier ordering)
{tier_ordered_list_of_open_items}

## Latest 5 ADRs
{adr_list}

## Current Test Baseline
{pytest_count} tests — last full run: {last_run_timestamp}

## Architecture Invariants (do not violate)
{appendix_b_from_technical_debt}

## Active Lock Codes (canonical)
{CANONICAL_LOCK_CODES from thresholds.py}
```

**The script reads from:**
- `TECHNICAL_DEBT.md` (open items)
- `docs/adr/README.md` (latest ADRs)
- Last cached pytest output (or runs a fast `-q --no-header` pass)
- `titan/config/thresholds.py` (`CANONICAL_LOCK_CODES`)

### Protocol Rules

#### Rule M1 — Advisor Context Gate
Before giving any AI advisor (ChatGPT, Gemini, Claude Chat) a task that touches
architecture, implementation patterns, or debt items, provide:

1. The relevant section of `docs/context-snapshot.md`.
2. The specific ADR(s) related to the task (if known).
3. The rule: *"Any recommendation that contradicts an existing ADR requires an explicit
   ADR amendment — it cannot be implemented directly."*

This is a human responsibility (the architect/engineer providing the context). It
cannot be fully automated because advisory sessions are conversational. But the
Context Snapshot makes it easy to paste the current state into any advisory session.

#### Rule M2 — Implementation Agent Pre-Task Checklist
Before any implementation agent (Codex, Claude Code) begins a task:

1. Read `docs/context-snapshot.md` (or regenerate it: `python scripts/generate_context_snapshot.py`).
2. If the task was sourced from an advisor recommendation: confirm it does not contradict
   any open or closed ADR.
3. Follow the SESSION_START protocol (ADR-0025, AGENTS.md §SESSION_START).

**This extends ADR-0025 S1–S5 with an additional step:**
> S0 (before S1): If this task originated from an advisor recommendation, identify the
> recommendation explicitly and check it against the ADR register before proceeding.

#### Rule M3 — Single Source of Truth for Architectural Decisions
Architectural decisions exist in exactly one place: `docs/adr/`. They do not exist in:
- ChatGPT conversation history
- Gemini conversation history
- Slack/Telegram messages
- GitHub issue comments

If an advisor conversation produces an architectural decision, that decision must be
captured as an ADR before implementation begins. Advisory conversations are ephemeral;
ADRs are durable.

#### Rule M4 — Conflict Resolution Protocol
If two agents produce contradictory implementations (FM-3):

1. **Stop both.** Do not merge either PR until the conflict is resolved.
2. The architect identifies which implementation is consistent with the ADR register.
3. The consistent one is merged. The other is closed with a comment referencing the
   relevant ADR.
4. If neither is fully consistent, a new ADR is written to resolve the conflict.

Rule M4 is a **human process rule** — it cannot be automated. But it prevents the
failure mode where a conflicting PR is merged because the reviewer did not know about
the parallel implementation.

## Options Considered

### Option A — Shared system prompt for all AI tools
Maintain a single "system prompt" document that is pasted into every AI tool session.

**Partially accepted.** `CLAUDE.md` already serves this purpose for Claude Code and
Codex. The problem is that ChatGPT and Gemini sessions are free-form — there is no
mechanism to ensure the system prompt is actually provided. The Context Snapshot
formalises what to share and when.

### Option B — Single AI tool for all roles (eliminate multi-agent stack)
Use only Claude Code for all tasks (implementation, review, architecture).

**Rejected.** Different tools have genuine strengths in different roles. Advisory
sessions (brainstorming, second opinions) are valuable precisely because they come from
a different model with different training. The multi-agent stack is a feature, not a
liability — the fragmentation is the liability, not the stack itself.

### Option C — Context Snapshot artifact + protocol rules (SELECTED)
Creates a machine-generated, always-current context document that any tool can consume.
Protocol rules define how advisors and implementers use it. Minimal overhead; maximum
consistency.

## Consequences

**Positive:**
- Advisor recommendations are grounded in the current ADR register, not a stale or
  incomplete understanding of the system.
- Parallel agent conflicts are detected before merge, not after regression.
- `CANONICAL_LOCK_CODES` and architecture invariants are explicitly communicated to
  every agent before each task.

**Neutral:**
- `generate_context_snapshot.py` must be kept current (new fields added when new
  governance artifacts are introduced). This is a low-maintenance task: add a new
  section to the script when a new category of context becomes relevant.

**Negative:**
- The protocol depends on the architect providing the Context Snapshot to advisors.
  If the architect forgets, the advisor operates without context. This is an improvement
  over the current state (no formal snapshot exists), but not a full solution.
