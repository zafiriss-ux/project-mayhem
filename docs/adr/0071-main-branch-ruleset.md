# ADR-0071: Το main δέχεται αλλαγές μόνο με PR και πράσινους ελέγχους

**Status:** ✅ Accepted (2026-10-24)
**Date:** 2026-10-24
**Author:** Zaf (Owner, έστησε τον κανόνα στο GitHub, 2026-10-24) / Claude (κείμενο)
**Related:** Project Mayhem Φάση 0 (εύρημα M0-06), audit του σχεδίου (DOC-05), ADR-0059 (ενιαίο
pytest), ADR-0061 (κανόνες εργασίας του owner), AGENTS §16 (υποχρεωτικές πύλες), D-151.

---

## Context

Η Φάση 0 βρήκε (M0-06) ότι οι πύλες του CI δεν δέσμευαν το main. Το workflow έτρεχε, αλλά τίποτα στο
GitHub δεν εμπόδιζε ένα merge ή ένα push όσο κάποιος έλεγχος ήταν κόκκινος ή δεν είχε τρέξει. Ο μόνος
κανόνας του repo (ruleset 16185828) απαγόρευε μόνο το force-push. Οι πύλες του AGENTS §16 ίσχυαν
δηλαδή μόνο όσο τις τηρούσε όποιος έκανε το merge.

Το repo έχει έναν άνθρωπο, τον owner. Τα PR τα γράφει και τα κάνει merge συνήθως ο Claude, με την
έγκριση του owner. Μια υποχρεωτική έγκριση από δεύτερο άνθρωπο δεν μπορεί να υπάρξει.

## Decision

Νέος κανόνας στο GitHub (ruleset 25769097) για το `main`:

1. **Μόνο μέσω PR.** Κανένα push κατευθείαν στο main. Απαιτούνται 0 εγκρίσεις, γιατί δεν υπάρχει
   δεύτερος άνθρωπος. Η έγκριση του owner δίνεται στη συζήτηση με τον Claude, όχι στο GitHub.
2. **Κανένα force-push και καμία διαγραφή** του main.
3. **13 υποχρεωτικοί έλεγχοι**, όλοι από αυτούς που τρέχουν σε κάθε PR:
   - Ruff Phase A (full repo, blocking)
   - Ruff Phase B (clean folders, blocking)
   - Test Suite (Python 3.12)
   - Invariants, policy and security scans
   - Dependency Drift Audit (unpinned + CVE gate)
   - Complexity Budget (module count ceiling)
   - Analyze (python), Analyze (actions), CodeQL
   - Bandit, DevSkim, devskim, gitleaks
4. **Εκτός λίστας μένουν οι έλεγχοι που δεν τρέχουν σε κάθε PR**: όσοι τρέχουν μόνο όταν αλλάζουν
   συγκεκριμένα αρχεία (Compose up, restart, persistence· Build and start TITAN.exe), όσοι τρέχουν
   μόνο στο main ή στο release (Docker images, GitHub Release, Windows zip, update-pip-graph), και
   ονόματα που δεν αντιστοιχούν σε έλεγχο. Ένας υποχρεωτικός έλεγχος που δεν τρέχει κρατά το PR
   κλειδωμένο για πάντα. Στην πρώτη εκδοχή του κανόνα, με 22 ονόματα, έτσι κλείδωσε το #1086 ώσπου
   να σβηστούν τα 9.

## Consequences

- **Θετικά:** οι πύλες του AGENTS §16 δεν εξαρτώνται πια από το ποιος κάνει merge. Κόκκινο CI σημαίνει
  ότι το merge δεν γίνεται, ούτε από τον Claude ούτε από λάθος.
- **Ουδέτερα:** οι έλεγχοι Compose και TITAN.exe μένουν προαιρετικοί στο GitHub. Όταν τρέχουν σε ένα
  PR, όποιος κάνει merge περιμένει να γίνουν πράσινοι, όπως πριν.
- **Αρνητικά:** ένας νέος έλεγχος στο CI, ή ένα μετονομασμένο job, δεν μπαίνει μόνος του στη λίστα.
  Όποιο PR αλλάζει το όνομα ενός από τους 13 jobs πρέπει να το πει στον owner, για να αλλάξει και ο
  κανόνας. Αλλιώς τα επόμενα PR κλειδώνουν.
- Ο κανόνας ζει στις ρυθμίσεις του GitHub, όχι στο repo. Αυτό το ADR είναι η μόνη του καταγραφή στο
  repo. Αλλαγή του κανόνα θέλει νέο ADR ή addendum εδώ.
- Τι **δεν** λύνει: δεν υπάρχει ανθρώπινος δεύτερος έλεγχος. Η ανεξάρτητη ανασκόπηση από AI που
  κάνει ο Claude σε κάθε PR δεν είναι πιστοποίηση από άνθρωπο.
